# 项目上下文：维护与稳定运行期

## 1. 项目定位

- 当前目标是保持线上系统稳定、可恢复和行为兼容，风险控制优先于交付速度。
- 修改前先说明影响范围、潜在回归、验证方法和恢复方案，再处理高风险变更。
- 优先选择最小且可回滚的修复，不借维护任务升级依赖、重构架构或改变无关行为。
- 涉及生产数据、发布、权限、计费或外部服务副作用时必须先获得明确授权。

## 2. 技术栈与架构

- 以目标项目实际部署配置、锁定文件和运行文档核验生产技术栈，不沿用过时说明。
- 修改前定位入口、上下游调用、持久化边界、外部依赖和现有保护机制。
- 对外部系统调用明确超时、重试、幂等和失败影响，不把网络成功当成业务成功。
- 保持公共接口、数据格式和存储语义向后兼容；必须破坏兼容时先制定迁移与回滚方案。

## 3. 常用命令

- 只使用目标项目已声明的复现、回归、构建、发布检查和回滚命令。
- 优先从 runbook、CI 配置、Makefile 和受控脚本获取命令，不凭经验拼装生产操作。
- 默认先执行只读诊断；任何写操作都要确认目标、范围和恢复方式。
- 找不到可靠命令或流程时停止操作并报告缺口，不在生产相关场景试错。

## 4. 代码规范

- 保持修改范围最小，遵循现有稳定模式，不进行无关重命名、格式化或抽象调整。
- 错误处理必须保留原因和上下文，不吞掉会影响告警、重试或回滚判断的错误。
- 改变配置、默认值、缓存、并发或重试行为时，明确说明运行时影响。
- 新增兼容分支时写明删除条件，避免临时修复永久积累。

## 5. 禁止事项与高危操作

- 不直接操作生产数据库，不执行未经评审的迁移、修复 SQL 或数据清理。
- 不绕过审批、发布门禁、灰度流程或审计要求直接变更生产环境。
- 不读取、输出或提交密钥、凭证、私有证书及真实用户敏感数据。
- 修改迁移、支付计费、身份权限、部署和 CI/CD 配置前，先说明影响并等待确认。
- 故障期间先控制影响、保留证据并遵循既有应急流程，不连续执行不可逆操作。

## 6. 测试与验证流程

- 缺陷修复必须覆盖复现用例、修复结果和关键相邻回归。
- 按项目要求运行完整回归、构建和静态检查；无法执行时明确风险，不声称验证完成。
- 发布前核对灰度、监控、告警和回滚条件；发布后验证关键业务指标与错误率。
- 故障处置优先恢复服务，再在证据完整的前提下定位根因。
- 完成标准同时包含功能正确、无已知回归、可观测和可恢复。

## 7. 外部文档引用

- 优先读取目标项目中已确认存在的发布 runbook、回滚手册、监控说明和事故复盘。
- 高风险操作只引用权威流程，不在长期记忆中复制可能过时的操作步骤。
